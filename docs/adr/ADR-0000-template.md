# ADR-XXXX: タイトル

一目で論点がわかるタイトルを記載する。可能な限り具体的で、それでいて簡潔なタイトルを心がける。

Date: YYYY/MM/DD ※作成日 (あとからおおよその提案時期がわかればよい)

## ステータス

**下書き**、提案済み、承認済み、却下、廃止、非推奨、置き換え済み

`提案済み` で提案して、チーム (またはチーム間) で合意ができたら `承認済み` にする。
別な議論などで決定が覆された場合、当該 ADR の決定を修正するのではなく、当該 ADR (ADR-0001 とする) のステータスを (`却下`: ADR-0002 に伴い) とした上で、別途新しく ADR を起こし (ADR-0002 とする)、そのステータスを (`提案済み`: ADR-0001 は破棄) などとするとよい。

## コンテキスト

この決定を行った背景・状況を記述する。技術的な制約、ビジネス要件、既存の問題点など、決定に至るまでの文脈を説明する。

## 決定

採用した選択肢と、その選択肢を採用した理由を記述する。

## 代替案

検討したが採用しなかった選択肢を記述する。それぞれについて、検討した理由と採用しなかった理由を説明する。

## 影響

この決定による影響・トレードオフを記述する。得られるメリットと、受け入れるデメリットや制約を明示する。

## 経過

決定後に判明したこと、実際にどうなったかを記述する。(任意。決定直後は空欄でよい)
