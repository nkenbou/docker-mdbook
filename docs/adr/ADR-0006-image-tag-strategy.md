# ADR-0006: イメージタグ戦略

Date: 2026/06/03

## ステータス

下書き、提案済み、**承認済み**、却下、廃止、非推奨、置き換え済み

## コンテキスト

GHCR に push するイメージのタグ命名規則が未定だった。
候補として以下が挙がっていた。

- `:latest` のみ
- mdBook のバージョンをタグに含める（例：`v0.4.40`）
- リポジトリ側のバージョン（Git タグ）をタグにする

このイメージは mdBook・mdbook-plantuml・mdbook-mermaid・PlantUML・Graphviz など複数ツールの組み合わせであり、単一ツールのバージョンではイメージ全体を一意に識別できない。

## 決定

リポジトリ自身の Git タグ（例：`v1.0.0`）をイメージタグとし、`:latest` も併用する。

```
ghcr.io/nkenbou/docker-mdbook:v1.0.0
ghcr.io/nkenbou/docker-mdbook:latest
```

各リリースに含まれるツールバージョンの組み合わせは CHANGELOG または README に記載する。

## 代替案

### `:latest` のみ

シンプルだが特定バージョンへの固定・ロールバックができず、再現性が低い。採用しなかった。

### mdBook のバージョンをタグに含める（例：`v0.4.40`）

mdBook バージョンが変わらないまま他のツール（PlantUML、Graphviz 等）を更新した場合、同じタグを上書きするか `-1`/`-2` のようなサフィックスを追加するかの二択になり、いずれも管理が煩雑になる。採用しなかった。

## 影響

- どのツールのバージョン更新でも一意な Git タグを発行することでイメージを識別できる
- `:latest` を併用することで、バージョンを意識しないユーザーも常に最新を取得できる
- イメージタグだけではどのツールが含まれるか判断できないため、CHANGELOG または README にバージョン一覧を記載する運用が必要になる
